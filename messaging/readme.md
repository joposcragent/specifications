# Схемы сообщений в топиках брокера сообщений Kafka

В этом каталоге содержится спецификация топиков (очередей, журналов) и структур сообщений в этих топиках.

## Структура каталога

1. На первом уровне находятся папки-топики. Имя папки соответствует имени топика.
2. Внутри папки-топика лежат yaml-файлы, каждый из которых содержит описание в формате OpenApi структуры сообщения ОДНОГО типа. Имя файла соответствует типу сообщения.
3. Файлы *.yaml на верхнем уровне каталога содержат общие компоненты, на которые ссылаются описания в конкретных типах сообщений.

## Сообщения

Каждое сообщение в Kafka содержит три компонента:

1. Ключ (`key`) - специальный заголовок, на основании которого брокер маршрутизирует сообщения между партициями:
   1. Брокер и гарантирует, что сообщения с одним и тем же ключом будут отданы консьюмерам в том же порядке, в котором они были опубликованы (по FIFO).
   2. Все сообщения в обязательном порядке должны содержать этот ключ без исключений.
2. Заголовки (`headers`) - коллекция ключ-значения, где ключ - строка, а значение всегда скалярные (не объекты).
   1. Коллекция заголовков сообщения описывается атрибутом `#/components/schemas/Message/properties/headers` в yaml-файле структуры сообщения:
      1. Имя каждой property - это имя имя заголовка;
      2. Тип property описывает тип и дефолтные значения заголовка;
      3. Тип значения заголовка всегда скалярный (не объект).
   2. Заголовки содержат простые метаданные сообщения, которые консьюмер до десериализации, содержащего сложную структуру, тела, чтобы принять решение, нужно ли обрабатывать это сообщение и вообще тратить ресурсы на десериализацию.
   3. У всех без исключения сообщений всегда задается минимальный набор заголовков:
      1. `key` - см п.1 выше;
      2. `type` - тип сообщения, строка, совпадающая с именем одного из файлов в каталогах-топиках;
      3. `createdAt` - момент времени, когда сообщение было опубликовано в топике;
      4. `schemaVersion` - номер версии структуры в формате semver.
   4. Все заголовки передаются только и исключительно в коллекции `headers` сообщения, дублирование заголовков в теле сообщения недопустимо.
3. Тело (`payload`) - JSON произвольной структуры
   1. Структура тела сообщения описывается компонентом `#/components/schemas/Message/properties/payload`;
   2. Тело сообщения содержит то и только то, что описано в `#/components/schemas/Message/properties/payload` и дублирование в теле коллекции заголовков бессмысленно и недопустимо.
