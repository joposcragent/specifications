# Планировщик (orchestration-scheduler)

## Назначение и маршрут

- **Раздел меню:** Настройки → **Планировщик**.
- **Маршрут:** `/settings/scheduler` (устаревший `/scheduler` перенаправляет на этот путь).
- Реализация: [`web-front`][web-front-repo].

Экран просмотра и правки настроек (`next_run`, интервал между запусками в виде ISO-8601 duration в поле `interval`) по всем значениям перечисления типов задач, а также принудительного запуска джоба.

## Базовый URL и прокси

Клиент HTTP использует переменную **`VITE_ORCHESTRATION_SCHEDULER_BASE_URL`**. Пустое значение — запросы на **тот же origin**, что и SPA; в Docker **nginx** фронта проксирует префикс **`/orchestration-scheduler/`** на сервис `orchestration-scheduler`; в dev **Vite** — proxy на планировщик (см. корневой [README](../README.md) и `vite.config`).

## Макет: таблица

Колонки (слева направо):

| Колонка | Источник данных | Поведение |
|---------|-----------------|-----------|
| Джоб | `jobType` из элемента списка | Только отображение (моноширинный текст). |
| (кнопка) | — | Символ запуска; открывает модалку подтверждения принудительного запуска. |
| Последний запуск | `previousRun` | Только отображение; значение `null` — строка **`null`**. Иначе дата/время инстанта из API в **локали и часовом поясе клиента** (как `formatDisplayDateTime`); подсказка при наведении — полный локальный формат. |
| Следующий запуск | `nextRun` | Как гиперссылка; `null` — **`null`**. Иначе — **локаль клиента** (как выше). Клик — модалка редактирования; в поле ввода по-прежнему строка из API (ISO с поясом) для сохранения без потери точности. |
| Интервал | `interval` | Как гиперссылка (моноширинный текст); `null` — **`null`**. Клик — модалка редактирования. Значение — [Internet Duration][internet-duration] (`PT1H`, `PT6H`, …). |

При открытии экрана выполняется **`GET /settings/list`**; тело ответа — объект со свойством `list` (массив элементов настроек по контракту OpenAPI).

## Модалка: следующий запуск или интервал

1. Поле ввода предзаполняется текущим значением (для `null` — пустая строка; в таблице при этом по-прежнему показывается **`null`**).
2. **Отмена** и клавиша **ESC** закрывают модалку без запроса.
3. **Сохранить** отправляет соответственно **`PUT /settings/next-run?jobType=…`** или **`PUT /settings/interval?jobType=…`** с телом JSON `{ "value": "…" }` (`next-run` — `date-time`; `interval` — строка duration по [Internet Duration][internet-duration]), затем закрывает модалку и снова запрашивает **`GET /settings/list`**.
4. При ответе с ошибкой (в т.ч. **400** / **500**) показывается текст ответа, если сервер вернул **`text/plain`** (как в спецификации scheduler), иначе — общее сообщение об ошибке сети.

## Модалка: принудительный запуск

1. Текст вопроса: «Вы уверены, что хотите принудительно запустить джоб?».
2. **Нет** и **ESC** закрывают модалку без запроса.
3. **Да** вызывает **`POST /execute?jobType=…`**; при успехе модалка закрывается и список обновляется (`GET /settings/list`).
4. Ошибки отображаются так же, как в модалке редактирования.

## Открытие и обновление

1. При первом входе на `/settings/scheduler` — индикатор загрузки, затем таблица по ответу `GET /settings/list`.
2. После успешного сохранения или принудительного запуска — повторная загрузка списка.
3. При **F5** — повтор сценария открытия.
