# Таблица вакансий и карточка (модальное окно)

## Где используется

Один компонент панели таблицы применяется:

- на **дашборде** (`/`) — пресет отбора «релевантные в рассмотрении»;
- на экране **«Вакансии»** (`/vacancies`) — полный список с сортировкой по дате загрузки на сервере.

Маршруты и пресеты зафиксированы в реализации роутера; контракт данных — [OpenAPI job-postings-crud][job-postings-crud-openapi].

## Модальное окно карточки вакансии

### Открытие

- **Триггер:** клик по **названию** (`title`) в строке таблицы (рядом остаются отдельные действия: заметки, на дашборде — промпт).

### Содержимое

- Отображаются поля сущности вакансии в формате списка определений (`dt` / `dd`): идентификаторы (`uuid`, `searchQueryUuid`, `uid`), `url` (как ссылка), `company`, `relevance`, текстовые статусы оценки и рассмотрения, даты публикации и меток времени (`publicationDate`, `createdAt`, `updatedAt`), краткое представление `contentVector`, полный текст `content` в прокручиваемой области.
- Подписи полей (`dt`): цвет текста зафиксирован для читаемости (нейтральный серый, не «бледный» secondary-текст темы).
- Поля дат в формате **timestamptz** / дата-время: в ячейке — локализованная дата (`toLocaleDateString()`); при наведении — **tooltip** с `toISOString()`.

### Размер окна

- Карточка допускает **изменение ширины и высоты** пользователем (встроенное поведение `resize` в браузере).
- При уменьшении **высоты** область с полями получает **вертикальный скролл**; заголовок карточки и блок кнопок остаются доступными (flex-колонка, прокрутка у тела).
- При увеличении **ширины** колонка со **значениями** (`dd`) расширяется за счёт сетки (`1fr`, `min-width: 0`, перенос длинных строк).

### Кнопка «Оценить» (принудительная переоценка)

- **Назначение:** запустить **синхронную переоценку** текущей вакансии на сервисе оценивания, в том числе когда статус оценки уже не «ожидает модели» (например, уже **RELEVANT** — повторный прогон допускается для одиночного вызова с UI).
- **Запрос:** `POST /evaluate/sync/{jobPostingUuid}`  
  Контракт: [OpenAPI job-postings-evaluator][job-postings-evaluator-openapi], тег `evaluate`.
- **Базовый URL:** переменная **`VITE_JOB_POSTINGS_EVALUATOR_BASE_URL`**. Пустое значение — запросы на **тот же origin**, что и SPA; в Docker **nginx** фронта проксирует префикс **`/evaluate/`** на сервис `job-postings-evaluator`; в dev **Vite** — proxy на эвалуатор (см. `vite.config`).
- **Тело запроса:** отсутствует. Заголовок `X-Joposcragent-correlationId` (UUID родительского async-job в `orchestration.async_jobs`) — опционально по контракту API.
- **Успех (2xx):** после ответа выполнить **`GET /job-postings/{jobPostingUuid}`** (CRUD), обновить данные в открытой модалке и соответствующую строку в таблице (без полного перезапроса всего списка обязательно, но допустимо).
- **Ошибка:** показать сообщение (например, snackbar); учитывать **404** / **5xx** от evaluator или CRUD.

Связанный бэкенд: семантика одиночного `evaluate/sync` описана в сервисе оценивания (переоценка не ограничивается только статусами NEW/PENDING для этого HTTP-вызова).

### Прочие кнопки в подвале карточки

- **Закрыть** — закрыть модалку без сохранения.
