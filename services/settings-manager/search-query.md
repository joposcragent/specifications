# Контроллер управления поисковыми запросами

Работает с PostgresSQL:

- База данных `joposcragent`
- Схема `settings`
- Таблица `search_queries` (поля: `uuid`, `name`, `query`, `content_relevance`, `notification_relevance`, `is_active`, `is_lazy_scraping`, `created_at`, `updated_at`)

Пороги релевантности хранятся **на уровне строки поискового запроса** (не глобальная таблица порогов).

## Получение списка настроенных поисковых запросов

`GET /search-query/list`

| Входной параметр | Источник       | Описание                    |
|------------------|----------------|-----------------------------|
| `{activeOnly}`   | query-параметр | фильтр по активным азпросам |

Алгоритм работы:

1. Выбирает из таблицы `search_queries` строки согласно фильтру `{activeOnly}`
2. Возвращает JSON-массив объектов `SearchQueriesItem`
3. При возникновении любого не перехваченного исключения возвращает `HTTP 500` с текстом исключения в теле ответа

## Добавление нового поискового запроса

`POST /search-query/{entityUuid}`

- `{entityUuid}` — path-параметр, UUID поискового запроса.
- Тело запроса — `application/json`: обязательные поля `name`, `query`, `contentRelevance`, `notificationRelevance` (числа от 0 до 1); опционально `isActive`, `isLazyScraping` (если не переданы, сервер применяет значения по умолчанию `true` и `false`).

Алгоритм работы:

1. Проверяет наличие в таблице `search_queries` строки с `uuid` = `{entityUuid}`
   1. Если строка найдена, возвращает `HTTP 409`
2. Вставляет строку с переданными полями и метками времени
3. При успешной фиксации изменений в БД возвращает `HTTP 200`
4. При возникновении любого не перехваченного исключения возвращает `HTTP 500` с текстом исключения в теле ответа

## Обновление поискового запроса

`PATCH /search-query/{entityUuid}`

- `{entityUuid}` — path-параметр, UUID поискового запроса.
- Тело запроса — `application/json`: любое непустое подмножество полей `name`, `query`, `contentRelevance`, `notificationRelevance`, `isActive`, `isLazyScraping`.

Алгоритм работы:

1. Проверяет наличие в таблице `search_queries` строки с `uuid`=`{entityUuid}`
   1. Если строка отсутствует, возвращает `HTTP 404`
2. Если в теле не указано ни одного допустимого поля, возвращает `HTTP 400`
3. Обновляет переданные поля; при изменении выставляет `updated_at` = `now()`
4. При успешной фиксации изменений в БД возвращает `HTTP 200`
5. При возникновении любого не перехваченного исключения возвращает `HTTP 500` с текстом исключения в теле ответа

## Удаление поискового запроса

`DELETE /search-query/{entityUuid}`

| Входной параметр | Источник      | Описание                |
|------------------|---------------|-------------------------|
| `{entityUuid}`   | path-параметр | UUID поискового запроса |

Алгоритм работы:

1. Проверяет наличие в таблице `search_queries` строки с `uuid`=`{entityUuid}`
   1. Если строка отсутствует, возвращает `HTTP 404`
2. Удаляет строку
3. При успешной фиксации изменений в БД возвращает `HTTP 200`
4. При возникновении любого не перехваченного исключения возвращает `HTTP 500` с текстом исключения в теле ответа

## Получение поискового запроса

`GET /search-query/{entityUuid}`

| Входной параметр | Источник      | Описание                |
|------------------|---------------|-------------------------|
| `{entityUuid}`   | path-параметр | UUID поискового запроса |

Алгоритм работы:

1. Выбирает из таблицы `search_queries` строку, у которой `uuid` = `{entityUuid}`
   1. Если такой строки нет, возвращает `HTTP 404`
2. Возвращает объект `SearchQueriesItem`, используя данные найденной строки
3. При возникновении любого не перехваченного исключения возвращает `HTTP 500` с текстом исключения в теле ответа
