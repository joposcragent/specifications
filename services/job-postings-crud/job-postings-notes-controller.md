# Контроллер заметок к вакансии

Работает с PostgresSQL:

- База данных `joposcragent`
- Схема `job_postings`
- Таблица `postings`, столбец `notes`

## Получение заметки

`GET /notes/{jobPostingUuid}`

| Входной параметр      | Источник      | Описание                 |
|-----------------------|---------------|--------------------------|
| 📌 `{jobPostingUuid}` | path-параметр | Внутренний UUID вакансии |

Алгоритм работы:

1. Ищет в таблице `postings` строку с `uuid` = `{jobPostingUuid}`
   1. Если строка не найдена, возвращает `HTTP 404`
2. Формирует JSON-объект с полем `text`:
   1. Если `notes` в строке равен `NULL`, `text` = пустая строка `""`
   2. Иначе `text` = значение `notes`
3. Возвращает `HTTP 200` с телом `application/json`
4. При возникновении любого не перехваченного исключения возвращает `HTTP 500` с текстом исключения в теле ответа

## Сохранение заметки

`POST /notes/{jobPostingUuid}`

| Входной параметр      | Источник      | Описание                                      |
|-----------------------|---------------|-----------------------------------------------|
| 📌 `{jobPostingUuid}` | path-параметр | Внутренний UUID вакансии                      |
| 📌 тело запроса       | JSON          | Объект с полем `text` (строка), полная замена |

Алгоритм работы:

1. Парсит тело как JSON; если тело отсутствует, JSON некорректен или нет поля `text` / тип `text` не строка — возвращает `HTTP 400`
2. Ищет в таблице `postings` строку с `uuid` = `{jobPostingUuid}`
   1. Если строка не найдена, возвращает `HTTP 404`
3. Устанавливает `notes` = значение `text` из тела, `updated_at` = текущий момент времени в UTC (аналогично обновлению при `PATCH` в [контроллере управления вакансиями][job-postings-controller])
4. Возвращает `HTTP 200` с пустым телом
5. При возникновении любого не перехваченного исключения возвращает `HTTP 500` с текстом исключения в теле ответа
